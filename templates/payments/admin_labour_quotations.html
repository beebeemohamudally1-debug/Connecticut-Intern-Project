Data comes from the view as `page`: page.stats -> review, pending, revision, accepted (counts) page.customers -> names for the customer filter page.quotes -> one row per labour quotation, newest update first: reference -> 'LQ-204' (payments.Quotation id) request -> 'REQ-2085' (quotation.request, a bookings.ServiceRequest) customer -> request customer full name service -> request service / title amount -> quotation.total_amount (or the handyman estimate while under review) amount_note -> short note under the amount for estimate rows ('Handyman estimate'), else '' updated_at -> last change date status -> 'review' | 'ready' | 'handyman' | 'pending' | 'revision' | 'accepted' | 'rejected' | 'cancelled' status_label -> 'Needs review' | 'Needs quote' | 'Awaiting handyman' | 'Awaiting customer' | 'Changes requested' | 'Accepted' | 'Declined' | 'Cancelled' handyman -> the handyman who made the labour estimate (full name) url -> that quotation's page (review page when under review, details page for the others) ONE ROW PER REQUEST: show the latest quotation if there is one, otherwise the labour estimate. Estimate rows: submitted = review, approved with no quotation yet = ready (action "Prepare quote"), revision_requested = handyman (the admin asked the handyman to revise), rejected = rejected. Quotation rows: sent = pending, revision_requested or revised = revision, accepted, declined = rejected, cancelled. The list needs an updated date for each row. BACKEND: payments.Quotation has no labour/material type, handyman estimate, "revision" status or updated date yet. Suggested mapping: under review = draft, pending = sent, accepted = accepted, rejected = declined, revision = new status. Search, customer and status filters and page buttons work in the browser on the rows sent (5 per page).
