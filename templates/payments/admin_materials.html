View: payments.views.admin_materials Context: purchase_requests -> MaterialPurchaseRequest list (newest first), each with request, handyman, quotation (the material quotation, once forwarded) and, from the view: receipt_list, receipts_waiting, approved_total, difference, ready_to_schedule (both quotations accepted and paid) receipts -> every MaterialReceipt (not used on this page) Flow (FR-A-9 part B): the admin approves the purchase request and sends the material quotation to the customer (forward()); the customer approves it; the handyman buys and uploads receipts; the admin reviews them. The material quotation is then paid with the service quotation (part C), and once both are paid the Receipts pop-up offers Schedule Appointment. Stage of each purchase request (data-status): admin -> submitted, waiting for the admin (Review pop-up) customer -> forwarded; the quotation is with the customer receipts -> quotation approved, receipts waiting for review (Receipts pop-up) accepted -> quotation approved, no receipt waiting declined -> the customer declined, or the quotation was cancelled rejected -> the admin rejected the purchase request none -> estimated cost 0: the handyman says no materials are needed (team rule, see accounts.admin_payments.materials_state). Not forwarded: the job is labour only. Forward / Reject post to payments:material_request_action (action forward | reject, total, note). Receipts are only shown here (view only): they are approved or rejected on the Payment Status page (accounts_admin:payment_status), which the Receipts pop-up links to. The number cards, search, filters and pages work in the browser on the rows sent. {% endcomment %} {% block title %}Material Quotations | HandyConnect{% endblock %} {% block page %}material-quotes{% endblock %} {% block crumb %}Material Quotations{% endblock %} {% block content %}
